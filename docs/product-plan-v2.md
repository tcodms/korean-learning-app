V1 호랑이 캐릭터와 주황 계열 팔레트를 사용한다. 홈·학습 선택 수정안 design/tiger-v1-orange-home-learn.png를 전 화면의 색상 기준으로 삼는다. 카테고리마다 보라·초록·파랑 등 강한 색을 나누지 않고, 주황의 밝기·채도 차이와 아이콘·텍스트로 구분한다. 큰 면적은 크림·옅은 살구색, 주요 동작은 진한 주황색, 본문은 짙은 중성색으로 구성한다. 아래의 미확정 브랜드·색상 관련 서술보다 이 결정과 프로젝트 AGENTS.md가 우선한다.

## 1. 서비스 방향과 이번 기획의 기준

외국인 학습자가 일상에서 필요한 한국어 단어·문법·표현을 짧은 문제로 익히고, 듣고 이해하며, 필요한 문장을 스스로 구성하도록 돕는 모바일 앱이다.

서비스의 중심은 시험 급수 달성이 아니라 한국어의 이해와 활용이다. TOPIK은 향후 선택 가능한 목적별 코스의 하나로 검토한다. 기존 korean-app-design-brief.md는 TOPIK·실전 회화가 포함된 이전 참고 문서이며, 새 개발 범위는 본 기획안을 기준으로 한다.

확정된 사용자 의도:
- 말해보카와 같은 짧은 입력·선택·카드 조합 학습을 참고한다.
- 어휘·리스닝·문법·표현을 학습 영역으로 구성한다.
- 실전 회화 기능은 현재 개발 범위에서 제외한다. 음성 대화, 음성 답변 평가, 발음 채점도 포함하지 않는다.
- 사용 가능한 데이터로 작은 완성본을 빠르게 만들고 단계적으로 확대한다.

아직 확정되지 않은 구현 가정:
- 첫 설명 언어는 영어로 제안한다. 한국어 학습 문장과 설명 언어는 별도로 관리한다.
- 첫 대상은 한글을 읽을 수 있는 성인 초급 학습자로 제안한다.
- 플랫폼은 Android 우선 실기기 검증, iOS 확장 가능 구조로 제안한다. 팀의 기존 기술과 배포 대상에 따라 최종 선택한다.
- 이름, 캐릭터, 색상, 수익 모델은 미확정이다. 이전 브리프의 호랑이 캐릭터는 선택안이다.

## 2. 누구의 어떤 문제를 해결하는가

핵심 대상은 한글과 기초 단어를 조금 알지만 문장을 만들기 어렵거나, 외운 표현을 다른 상황에 적용하지 못하는 학습자다. 한국 여행·문화 콘텐츠·일상생활 등 학습 목적은 다를 수 있다.

주요 문제와 제공 가치:
| 학습자의 어려움 | 앱의 대응 |
| --- | --- |
| 단어 뜻은 아는데 문장에서 쓰지 못함 | 문맥 빈칸과 문장 완성으로 연습 |
| 조사·어미가 헷갈림 | 같은 문형에서 차이를 비교하고 다시 적용 |
| 글로는 알지만 들으면 놓침 | 같은 표현을 음성으로 듣고 새 문장에서 확인 |
| 외운 예문만 기억함 | 단어·상황이 다른 변형 문항 제공 |
| 무엇을 복습할지 모름 | 오답과 힌트 사용 이력으로 복습 제안 |
| 공부할 시간이 짧음 | 5~10문항 단위로 완료하고 이어하기 |

한글을 처음 배우는 사용자에게는 진입 시 요구 수준을 알린다. 한글 입문 코스는 후속 확장 항목이다. 초급 문장을 읽을 수 있다는 것과 특정 공인 등급을 보유했다는 것을 동일하게 취급하지 않는다.

## 3. 서비스의 학습 원칙

1. 뜻을 알아보는 연습에서 직접 떠올리고 문장을 구성하는 연습으로 이동한다.
2. 같은 문장을 무조건 반복하기보다 같은 학습 항목을 다른 문장과 상황에서 확인한다.
3. 어휘·문법·표현·듣기를 공유 학습 항목으로 연결한다.
4. 정답 여부뿐 아니라 정답 근거, 자연스러운 용법, 필요한 경우 다른 허용 표현을 설명한다.
5. 학습 목적과 입력 부담에 따라 카드형과 입력형을 선택한다.
6. 앱 내부 단계와 학습 기록을 실제 회화 능력이나 공인 급수로 단정하지 않는다.

차별화 가설은 한국어 조사·활용·높임말의 차이를 이해하기 쉽게 설명하고, 배운 표현을 문장 구성과 듣기로 연결하는 경험이다. 기존 앱에 없는 기능이라고 주장하지 않으며 사용자 검증으로 가치를 확인한다.

## 4. 전체 사용자 흐름

설명 언어 선택 → 한글 읽기 가능 여부·시작 수준 선택 → 관심 주제·하루 목표 선택 → 첫 학습 → 즉시 피드백 → 재도전·완료 → 다음 복습

초기 설정은 최소화하고 관심 주제와 목표는 건너뛸 수 있게 한다. 정교한 레벨 테스트를 필수 관문으로 두지 않는다. 첫 사용은 게스트로 시작할 수 있도록 설계한다.

학습 진입 경로:
- 오늘의 추천: 복습할 내용과 새로운 내용을 묶어서 시작한다.
- 영역별 학습: 어휘·리스닝·문법·표현 중 하나를 선택한다.
- 주제별 학습: 음식·쇼핑·교통 등 관심 있는 상황으로 시작한다.
- 내 학습장: 저장한 단어·표현과 오답을 다시 학습한다.

첫 완성본에서는 영역별 학습과 한 개 주제만 제공한다. 추천과 저장 학습장은 후속 단계로 추가한다.

## 5. 핵심 학습 기능

### 5.1 어휘 학습

목적: 단어의 의미를 알고 문맥에서 적절하게 사용한다.

문제 예시:
- 뜻 선택: 학교 → school
- 문맥 빈칸: 저는 ___에 가요. (I go to school.)
- 듣고 단어 선택: 음성을 듣고 대응하는 단어 선택
- 유사어 구분: 사다/팔다 등 혼동하기 쉬운 항목 비교

정답 후 품사, 해당 문맥의 뜻, 예문, 문장 음성, 필요한 활용형을 확인한다. 같은 표기의 여러 뜻은 뜻 단위로 구분한다. 보기로 등장한 단어는 배운 단어 수에 자동으로 포함하지 않는다.

확장: 그림 연결, 주제별 단어장, 개인 저장, 동의어·반의어, 활용형 연습.

### 5.2 문법 학습

목적: 조사·어미·문형의 의미 차이를 익히고 문장을 구성한다.

문제 예시:
- 조사 선택: 저는 사과___ 좋아해요. → 를
- 카드 배열: [저는] [사과를] [좋아해요]
- 활용 완성: 어제 학교에 ___. (가다 → 갔어요)
- 오류 수정: 목표 조사나 활용 부분을 찾아 올바르게 고침

한 문제에 하나의 중심 학습 목표를 둔다. 조사·어미의 긴 설명을 문제 전에 강제하지 않고 짧은 요약과 예문을 해설에 제공한다.

한국어는 가능한 어순이 여러 개이므로 배열 문제는 명확한 문맥과 허용 배열 목록을 가진 문항부터 사용한다. 목표 말투와 다른 답이 문법적으로 맞을 때는 오답 이유를 구체적으로 표시한다.

### 5.3 표현 학습

목적: 상황과 의도에 맞는 표현을 기억하고 새로운 상황에 적용한다.

어휘는 단어의 의미, 문법은 구성 규칙, 표현은 상황에서 쓰는 묶음에 초점을 둔다. 예: 주세요, -고 싶어요, 괜찮아요, 잠시만요.

문제 예시:
- 의도에 맞는 표현 고르기: 물을 정중하게 요청하는 표현
- 빈칸 완성: 물 좀 ___. → 주세요
- 카드 조합: [거기] [어떻게] [가요]
- 상황 적용: 같은 요청 패턴을 물·메뉴판·봉투 등으로 확장

높임말/반말, 정중함, 주로 쓰는 관계와 상황을 태그로 관리한다. 초기 콘텐츠는 해요체 중심으로 일관되게 구성하고, 반말·격식체 비교는 후속으로 확장한다.

### 5.4 리스닝 학습

목적: 배운 단어와 표현을 소리로 알아듣고 의미를 이해한다.

문제 유형:
- 듣고 뜻 또는 상황 고르기
- 듣고 빠진 단어 고르기
- 들은 문장을 카드로 구성하기
- 짧은 대화를 듣고 가격·시간·장소 등 정보 고르기

음성 재생, 반복, 속도 조절, 답변 후 대본과 번역을 제공한다. 대본 보기와 반복 횟수는 도움 사용으로 기록할 수 있다. 처음부터 대본을 노출하지 않는다.

선정한 대본의 음성을 미리 준비해 재생한다. 학습 때마다 음성을 생성할 필요는 없다. 짧은 대화 음성을 듣는 것은 가능하지만 사용자가 음성으로 대화하는 기능은 제외한다.

## 6. 공통 문제 화면과 상호작용

첨부 이미지는 다음 상호작용의 참고 자료로 사용한다: 상단 진행률, 중앙의 큰 문제 카드, 빈칸 입력, 선택 가능한 단어 카드, 힌트, 확인 버튼, 정답 후 다음 문제. 브랜드 색·문구·화면 자산을 그대로 복제하지 않는다.

공통 구성:
- 상단: 나가기, 진행률, 음성·효과 설정
- 중앙: 지시문, 문맥·번역, 학습 문장과 빈칸 또는 조립 영역
- 하단: 입력창/보기/카드, 힌트, 제출 버튼
- 피드백: 정답 상태, 정답 문장, 짧은 해설, 음성 재생, 다음 버튼

입력형은 한글 키보드가 필요함을 안내하고 지원하는 문항에서는 카드형으로 전환할 수 있다. 카드형 전환은 학습 방식 기록에 남긴다.

오답은 설명 후 한 번 재도전할 수 있게 하고, 계속 틀려도 정답을 확인한 뒤 진행할 수 있게 한다. 알 수 없어요 동작을 별도로 제공한다. 정답 확인 후의 재입력은 첫 시도 정답으로 계산하지 않는다.

필수 상태: 로딩, 입력 전, 제출 중 중복 방지, 정답, 오답, 힌트 사용, 음성 로딩·재생 실패, 중단 확인, 이어하기, 학습 완료, 기록 없음.

접근성: 글자 확대에 대응하고 색상만으로 정오답을 전달하지 않는다. 터치 영역과 키보드 노출 시 버튼 위치를 확인한다. 효과음·진동을 끌 수 있게 한다.

## 7. 학습 코스와 개인화

전체 코스는 일상 주제와 학습 단계의 두 축으로 구성한다.

주제 예: 인사·소개, 음식·주문, 물건 사기, 시간·약속, 교통·길 찾기, 집·학교·직장, 취미·감정.

앱 내부 단계 예:
- 시작: 짧은 기본 문장과 해요체
- 확장: 과거·미래, 요청, 이유, 비교
- 활용: 여러 문장의 연결, 상황별 말투·표현 구분

이 단계는 콘텐츠 편성용이며 공인 시험 급수에 자동 대응시키지 않는다.

하나의 학습 항목은 여러 영역에서 재사용한다. 예를 들어 요청 표현은 어휘의 물건 이름, 문법의 주세요, 표현의 정중한 부탁, 듣기의 주문 이해로 이어진다.

초기 개인화는 선택 수준·관심 주제·오답·도움 사용으로 다음 묶음을 정하는 단순 규칙으로 시작한다. AI 적응형 추천을 첫 필수 기능으로 두지 않는다.

## 8. 복습과 학습장

기본 복습:
- 학습 종료 시 틀린 항목을 다시 확인한다.
- 다음 학습에서 이전 오답 일부를 우선 제안한다.
- 정답이라도 힌트를 사용한 항목은 별도 도움 사용 상태로 저장한다.
- 같은 항목의 다른 문항을 제공할 수 있으면 우선 활용한다.

복습 일정 초안은 다음 날·3일 뒤·7일 뒤처럼 단순하게 시작하고 학습 결과에 따라 조정한다. 간격은 검증 전의 제품 설정값이며 기억 효과를 보장하는 수치로 표현하지 않는다.

학습장 확장: 단어·표현 저장, 뜻·예문·음성 상세, 주제·숙련 상태 필터, 저장 항목으로 복습 묶음 만들기. 장기 미접속 분량을 전부 강제로 쌓지 않고 오늘 할 분량을 제한한다.

## 9. 학습 통계와 동기부여

초기 통계:
- 영역별 푼 문제 수와 학습 일수
- 첫 시도 정답률
- 힌트 사용 및 재도전 기록
- 새로 학습한 고유 항목 수와 복습한 고유 항목 수
- 학습 이어하기 및 완료 이력

문제 제출 횟수, 고유 문제 수, 고유 학습 항목 수를 구분한다. 첫 시도 정답률에 재도전 정답을 섞지 않는다. 도움 없는 정답률은 힌트·대본·정답 보기 사용 여부를 함께 정의한다.

확장 통계: 실제 활동 시간, 주간 추이, 주제별 성취, 같은 학습 항목의 새 문제 정답률, 학습 캘린더. 학습한 단어 수를 전체 어휘력 추정치로 부르지 않는다.

동기부여 확장: 하루 목표, 연속 학습, 작은 완료 애니메이션, 배지, 캐릭터 반응. 랭킹·리그·꾸미기는 핵심 학습 검증 후 검토한다. 학습 횟수 제한과 복잡한 게임 재화는 첫 흐름에 넣지 않는다.

## 10. 데이터 확보와 콘텐츠 운영

### 10.1 데이터 확보 전략

공개 사전의 어휘·뜻풀이·예문·번역을 활용하고, 학습 순서와 문제 구성·보기·해설을 앱에 맞게 편집한다. 모든 학습 자료를 새로 집필하지 않아도 되지만, 이미 완성된 문제은행이 자동으로 제공되는 것은 아니다.

우선 검토 데이터:
- 국립국어원 한국어기초사전 API: 어휘·뜻·예문·활용·다국어 정보
- 이용 조건이 명확한 어휘 목록: 범위 선정 보조
- 자체 작성 문장·대본: 공개 자료로 충족되지 않는 상황과 변형 문항
- 이용 조건을 확인한 TTS 또는 녹음: 듣기 문장 음성

한국어기초사전은 별도 표시가 없는 자료에 CC BY-SA 2.0 KR을 적용하며 출처 표시와 변경 저작물의 동일조건 배포를 요구한다. 음성·이미지 등은 개별 조건이 적용된다. 번역 등 필드별 제공·권리 조건도 실제 수집 전에 확인한다. 공식 TOPIK 기출을 기본 콘텐츠의 필수 조건으로 삼지 않는다.

### 10.2 콘텐츠 제작 절차

학습 항목 선정 → 사용할 수 있는 자료 수집 → 예문·번역 선정 → 문제 템플릿 적용 → 오답 보기·해설 작성 → 언어·채점 검수 → 음성 확인 → 게시

AI는 문항·오답 보기·해설의 초안 작성에 활용할 수 있다. 검수 전 자동 게시하지 않는다. 첫 샘플은 팀 검토로 체험용 초안을 만들고, 사용자 대상 공개 전에는 한국어 교육 검수를 확보하는 것을 목표로 한다.

검수 항목:
- 목표 뜻이 명확하고 복수 정답이 생기지 않는가
- 한국어·번역이 자연스럽고 말투가 일관되는가
- 목표 문법 외의 불필요한 난도가 없는가
- 허용 답안과 해설이 일치하는가
- 오답 보기가 너무 쉽거나 의도치 않은 정답이 아닌가
- 대본과 음성이 일치하는가
- 출처·이용 조건·검수 상태가 기록되어 있는가

## 11. 데이터 구조와 채점 원칙

데이터는 학습 항목, 예문·음성, 문제, 사용자 시도로 나눈다.

| 데이터 | 주요 필드 |
| --- | --- |
| 학습 항목 | 항목 ID, 어휘/문법/표현 구분, 뜻 ID, 주제, 내부 단계, 선수 항목 |
| 예문·음성 | 한국어 문장, 언어별 번역, 말투, 대본, 음성 위치, 출처·권리 |
| 문제 | 문제 ID·버전, 영역, 유형, 학습 항목 ID, 지시문, 보기·카드, 허용 답안, 해설, 검수 상태 |
| 사용자 시도 | 시도 ID, 문제·버전, 첫 답변, 정답 여부, 힌트·대본 사용, 재도전, 소요 시간 |
| 복습 상태 | 학습 항목 ID, 최근 결과, 다음 복습일, 도움 사용, 관련 문제 이력 |

같은 뜻의 항목이 어휘·듣기에 등장하더라도 항목 ID를 공유한다. 문항은 독립 ID로 관리해 새 문제 적용 성과를 확인한다.

채점:
- 선택형은 보기의 고유 ID로 채점한다.
- 배열형은 허용 카드 순서 목록으로 채점하고, 사용 가능한 카드와 중복 카드 ID를 구분한다.
- 입력형은 한글 유니코드 정규화와 앞뒤 공백 정리를 기본 적용한다.
- 조사·띄어쓰기·문장부호 무시 여부는 문항 목적에 따라 지정한다. 모든 공백을 일괄 제거하지 않는다.
- 자유로운 장문 입력과 AI 채점은 현재 범위에서 제외한다.
- 허용 답안이 여러 개면 명시적으로 등록한다. 오타와 문법 오류는 구분할 수 있을 때만 구체적인 피드백을 제공한다.

첫 완성본은 로컬 JSON으로 시작하고, 데이터 로딩 부분을 분리해 이후 DB·CMS로 전환할 수 있게 한다. 문제 내용과 화면 코드를 분리한다.

## 12. 앱 정보 구조

출시형 기본 구조:
- 오늘: 이어하기, 오늘 목표, 추천 학습, 복습
- 학습: 어휘·리스닝·문법·표현, 주제·단계별 탐색
- 내 학습장: 저장 항목·오답·복습
- 기록: 학습량·정답률·캘린더
- 설정: 별도 진입. 설명 언어, 음성·효과, 계정, 알림, 출처·라이선스

첫 완성본은 홈 → 영역 선택 → 문제 → 피드백 → 결과를 구현하고, 빈 메뉴를 노출하지 않는다. 학습장과 기록은 실제 기능을 제공하는 시점에 추가한다.

## 13. 단계별 구현 범위와 완료 기준

### 1단계: 체험용 앱

목표: 실제 휴대폰에서 네 영역의 대표 학습 경험을 끝까지 확인한다.

- 한글 읽기가 가능한 초급자, 영어 설명을 첫 구현 가정으로 사용
- 한 주제인 물건 사기·요청하기를 중심으로 자체 샘플 및 이용 가능한 공개 자료 구성
- 어휘·문법·표현·듣기 각 4~6문항, 총 20문항 안팎을 제작 목표로 설정
- 선택형·빈칸 입력형·카드 배열형 공통 화면
- 힌트, 정답·오답, 짧은 해설, 다음 문제, 결과
- 준비된 듣기 음성 재생과 답변 후 대본
- 로그인·서버·결제 없이 로컬 데이터로 구동
- 콘텐츠 출처 표시와 샘플 안내

완료 기준:
1. 휴대폰에서 선택·입력·배열이 정상 동작한다.
2. 듣기 재생과 실패 시 재시도가 가능하다.
3. 제출 중복을 막고 첫 시도와 재도전을 구분한다.
4. 각 영역을 시작해 결과까지 진행할 수 있다.
5. 입력 키보드가 제출·해설 영역을 가리지 않는다.
6. 데이터 파일의 오류·누락을 점검하고 정답·해설이 일치한다.

### 2단계: 복습·기록 연결

- 기기 내 학습 기록 저장과 중단 후 이어하기
- 오답 재출제, 다음 학습의 복습 목록
- 새 학습·복습·힌트 사용을 구분한 통계
- 단어·표현 저장 및 기본 학습장
- 오늘 목표·연속 학습의 최소 형태

완료 기준: 앱을 다시 실행해도 기록과 복습 상태가 유지되고, 재도전이 첫 시도 통계를 바꾸지 않는다.

### 3단계: 콘텐츠·맞춤 학습 확대

- 음식·교통·시간 등 주제 확대
- 같은 학습 항목의 새 문항 추가
- 관심 주제·수준·복습 상태에 따른 추천
- 콘텐츠 관리용 편집·검수·게시 흐름
- 필요할 때 계정과 서버 동기화 추가
- 추가 설명 언어와 한글 입문 코스 검토

완료 기준: 검수한 콘텐츠를 앱 화면 코드 수정 없이 추가하고, 학습 항목 기준으로 관련 문제·복습이 연결된다.

### 4단계: 검증 결과에 따른 확장

검토 후보: 상황별 말투·높임말, 받아쓰기, 유사어 비교, 문장 변환, 콘텐츠 기반 표현 코스, TOPIK 선택 코스, 위젯·알림·캐릭터 성장.

영역·유형을 늘릴 때마다 자체 제작·기존 자료 활용·검수 비용을 평가한다. 실전 회화는 이번 로드맵의 확정 항목으로 포함하지 않는다.

## 14. 사용자 검증과 우선순위 판단

1단계부터 한글을 읽는 실제 초급 학습자에게 관찰 테스트를 진행한다. 이후 반복 사용을 확인한다.

확인할 질문:
- 별도 설명 없이 문제를 이해하고 제출할 수 있는가
- 입력형과 카드형 중 어떤 상황에서 부담을 느끼는가
- 해설을 보고 왜 틀렸는지 설명할 수 있는가
- 처음 보는 문장에서도 같은 학습 항목을 적용하는가
- 다음 날 다시 학습할 이유가 있는가

지표는 첫 학습 완료율, 중단 문항, 힌트 사용, 다음 날·7일 이내 재방문, 새 문항의 도움 없는 첫 시도 결과 등을 사용한다. 구체적인 성공 수치는 초기 관찰 후 설정하며, 문제 수 증가만으로 학습 효과를 판단하지 않는다.

리스닝의 중단 원인이 음성 품질이면 콘텐츠를 고치고, 입력형의 중단 원인이 한글 키보드라면 카드형 접근성을 보완하는 식으로 원인에 따라 개선한다.

## 15. 기술 구현 제안

팀의 기존 기술이 없다면 React Native + Expo + TypeScript를 후보로 사용한다. 실제 개발 전 저장소·팀 경험·대상 OS를 확인해 확정한다.

- 1단계: 로컬 JSON, 공통 문제 컴포넌트, 준비된 음성 재생, 세션 내 결과
- 2단계: SQLite 등 기기 내 영속 저장, 복습 규칙, 통계
- 3단계: 필요에 따라 Supabase 등 서버·인증·파일 저장 추가

리스닝은 음성 재생 기능이다. 마이크 권한·음성 인식·발음 분석·AI 실시간 회화가 필요한 구조로 만들지 않는다.

검증은 채점·복습·통계의 실제 오류 가능성이 있는 동작과 실기기 입력·음성·이어하기 흐름에 집중한다. 단계별 목표가 확인된 뒤 범위를 확대한다.

## 16. 개발 착수 시 산출물

1. 샘플 콘텐츠 목록과 출처·검수 상태
2. 대표 세 문제 유형과 학습 결과 화면의 동작 명세
3. 로컬 데이터로 실행되는 모바일 앱
4. 실기기 확인 결과와 다음 수정 목록

첫 작업 순서: 콘텐츠 형식 정의 → 대표 문항 작성 → 공통 문제 화면 → 채점·해설 → 듣기 연결 → 결과 → 실기기 확인.
